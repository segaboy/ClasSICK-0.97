# SPEC-0098 - Original PC diagnostic viewer

2026-11-05; SRC-0599. Original engineering design; no historical or emulator implementation input. This is a bounded Windows test frontend for one isolated, verified original PC disk. It displays the actual VM framebuffer and records only events delivered to its own foreground window. The separate relay uses the already-admitted public VirtualBox IMouse interface. It changes neither guest code nor the Qt frontend and establishes no release result until tested.

The [frozen brief](../development/tasks/pc-original-viewer.md) defines the fixed 1024x768 BGRX frame, complete-frame publication, relative-motion state, desktop/foreground checks, lifecycle cancellation, 4096-record cap and 300-second lifetime. Implementation clarification: a first mouse-move carrying a held button is suppressed; an actual down message after an observed release may establish a press on first position. A down following focus/leave/stale cancellation stays suppressed until a release is observed. Each event records a monotonic sequence and Windows uptime; no arbitrary command or path is accepted. The output is create-new. Invalid coordinates never perform signed-overflow arithmetic. A large jump releases a held guest button and disarms until released; it never silently clamps.

The host relay verifies the exact owned UUID/name, admitted disk/build and viewer process identity. It consumes bounded, sequential, validated events while that process is alive; events older than 1000ms are refused, never replayed. Any gap, malformed event or relay error stops the path and sends one neutral guest release through the same owned session. A frame pump uses the admitted screenshot interface, validates dimensions and emits atomic complete frames. Neither component injects Windows input or controls another app. Stop/error cleanup closes only owned processes and the isolated VM, preserving prior inventories and media.

The viewer may make one ordinary SetForegroundWindow request for its own newly created window, then reports the return value without treating it as acceptance. No thread attachment, modifier injection or foreground-lock setting is used. Read-only guard transitions report frame freshness, actual own foreground and Default desktop as three separate bits. Input still requires all three on each admission.

Pure motion/frame tests must precede GUI trials. Native GUI code is original reuse of reviewed platform/windows presentation/capture and tools/windows-input desktop-check patterns. No manual example or vendor implementation is input. Live outcomes must retain actual GUI event and API delivery logs alongside independently captured guest pixels. API success alone remains E2; an E3 claim requires causal GUI-to-guest evidence for this explicitly different frontend. E4, physical hardware and ordinary Qt capture remain separate. No package distribution of this diagnostic or runtime dependencies is authorized by this contract.
