# SPEC-0059 - PC native window boot binding

Accepted behavioral contract2026-10-22;SRC-0346..0348;ADR-0068;TEST-0070.
Independent platform engineering design,not historical Macintosh evidence.
Contract only:unimplemented,no new headers,fixtures,feature tests,build or trial.

Firmware-neutral session plus presentation bridge, and a thin current-UEFI gate. Not a BIOS loader, common handoff ABI, or claim that every 64-bit PC works. Neutral code takes no UEFI headers. Optional UEFI profiles keep their behavior. No firmware services after a real exit. UART bodies and their observer ABI stay unchanged and are not copied; this path may bypass them and then has no UART diagnostics.

## Boundaries
The caller-owned session reserves,and its bridge borrows,one ordinary-RAM Mono1 512x342 surface, stride 64, 21888 bytes; a 48-byte cursor payload; and one RGBA8 row of 4*physical width, width<=8192 so the row is <=32768. It never stores a full physical frame and never binds cursor or compositor storage to volatile framebuffer memory. It calls existing cs_fb_init and cs_fb_present only. Present accepts RGBA8 only. The session owns one window owner, one bus, one delivery receipt, and one keyboard queue of capacity 8. The UEFI wrapper establishes the full gate below before enabling this path. Proposed module boundaries: platform/pc/mono-present.[ch] for conversion/publication, platform/pc/window-session.[ch] for one exclusive native session, platform/uefi/window.[ch] for the current gate/clock/entry binding. Names are planned,not existing files. Shared apps/window-scene and core input/graphics retain their interfaces and acquire no UEFI types. This is not the future BIOS/UEFI payload ABI.

## Gate
Native caller supplies truthful live aligned storage,mappings and exclusive synchronous nonreentrant access;numeric spans cannot make arbitrary pointers readable. Preflight complete fixed argument spans,NULL/wrap/alias and the immutable borrowed graph before initialization or device effects. All writable state,canvas,payload,row,queue and diagnostics must be disjoint each other and from readonly descriptors/art/handoff/map;device framebuffer is a separate live writable span. Native object lifetimes remain valid through the whole session.
The UEFI wrapper requires real EXITED/status0,native descriptor readiness,validated map/owned spans and accessible memory windows,RSDP/PM-timer/ACPI8042 capability,framebuffer checks and exclusive131072-byte arena. Width>=512,height>=342;preserve existing target limits8192 and pitch limits;row4*width<=32768. Do not infer mapping validity from a declared address window. No firmware services after exit. Raw argument preflight refusal preserves all caller bytes and performs no I/O. A later gate failure may write only an already-validated diagnostic record;it starts no owner or controller and writes no framebuffer. Capability discovery/clock reads are not claimed to be effect-free security validation.
Future explicit -WindowDrawing / CLASSICK_WINDOW_DRAWING=1 is mutually exclusive with selected/outline modes. It runs until explicit external stop or fault,without a hidden60s deadline;any seconds parameter is validated metadata only. Existing timed modes retain their deadlines/Escape exit;existing continuous outline preview keeps SPEC-0050 behavior (including ignoring Escape). No current flag or script is installed here.

## Startup order
After gate/preflight and the one allocation plan,bind the RAM surface/cursor,begin owner with software buttons0,then cancel exactly once before input is enabled. Begin must return OK;cancel CHANGED. Begin/cancel are one startup batch:only after BOTH succeed publish the post-cancel image ONCE,then initialize/enable the sole controller poller. This avoids duplicate initial MMIO publication and does not wait for a mouse packet. Count remains0,coordinates stay centered and LEFT is suppressed until a real report observes release. If begin/cancel fails,retain its truthful owner/render prefix,publish nothing,and stop without automatic repair. If first publication fails,never enable the controller.
Unknown initial state deliberately suppresses a first held/down report,even if it might have been a newly made click. Do not invent a release or infer one from idle time. Test/setup instructions must require LEFT released and a brief mouse movement (a real released report) before qualification clicks;then a fresh press counts normally. Record suppression/arming status diagnostically. This is an engineering startup policy,not a physical-input qualification or universal mouse claim.

## Publication
left=floor((W-512)/2),top=floor((H-342)/2),unscaled. Black Mono bit1 becomes RGBA000000FF,white bit0 becomes FFFFFFFF;cs_fb_present writes device reserved byte0 for both supported RGB/BGR targets. No framebuffer reads or cursor saved-background storage in MMIO.
Preflight complete source,target,row and disjoint spans before writes,using existing cs_fb_init/cs_fb_present unchanged. First publication:construct each physical-width RGBA row white,overlay its512 logical pixels when it intersects the centered canvas,and present that row at(0,y). Successful completion covers every visible pixel once;pitch padding/storage tail stay untouched. Later publication converts342 logical rows and presents each512-pixel row at(left,top+y),leaving margins/padding/tail intact. Only one row workspace is used;no full physical RAM framebuffer. Source descriptors/workspace/art/target remain immutable except documented workspace writes while borrowed.
Every accepted RUNNING owner call (OK0 or CHANGED) publishes the coherent latest RAM canvas;OK0 can change cursor/bookkeeping. Startup is the explicit begin+cancel batch above. No publication for NONE,idle turns or a pre-effect owner refusal. A refusal preserves that owner's pre-effect bytes,but the session may enter terminal state and record diagnosis. Full row completion is software/API progress,not atomic scanout or proven tear-free hardware display.

## Poll turn
Each nonterminal turn clears its local delivery receipt to NONE/zero BEFORE clock sampling. A clock-value/stall failure stops before controller poll or owner delivery. Otherwise the sole poller calls cs_ps2_bus_poll_delivery once (at most once per turn);on result above CS_PS2_READY stop without using a receipt. Then pop at most8 keyboard records,stopping at EMPTY;any other queue error terminates before mouse delivery. Startup ACK/BAT/configuration and keyboard data are not mouse samples. Space/Escape neither add UI clicks nor stop this new profile.
Only after those checks:PACKET goes once through cs_pc_window_packet;LOST goes once through cs_window_input_cancel;NONE makes no owner call. Publish after accepted owner result;on refusal/fault stop. The UI count is only owner.counter/product.inputs;never add bus.left or keyboard totals. Identical fresh reports still deliver;packet/error totals never establish freshness. A queue/clock/controller terminal preserves all earlier completed turns and never replays this turn later. No second poller,decoder,resample or copied receipt reuse. Timer sampling/wrap assumptions remain the existing profile,not proof of arbitrary hardware timing;later latency/qualification must measure this path.

## Faults
Separate owner failure (retained logical/consumer/render prefix,possibly partial RAM) from presentation refusal after a complete RAM frame. Stop input on either;no automatic repair,re-begin,rollback,count decrement,replay or stale restore. A failed publication can have earlier completed rows visible. Existing cs_fb_present reports ordinary validation refusals;it does not detect or recover arbitrary MMIO exceptions. An exception may interrupt a row and leave visibility unknown. Do not invent a C error or completed-frame claim for it.
Clock/controller/queue terminals issue no new owner cancellation or publication;the last accepted prefix remains truthful,not an active drag session. Explicit external stop ends polling without a new controller shutdown recipe. After any stop,retain the borrowed graph/pixels for diagnosis until all calls are quiescent and the owner explicitly detaches cursor borrows through its existing protocol;no automatic re-begin or buffer reuse. There is no continued input after terminal state.
Use a distinct bounded versioned window diagnostic record within the owned trace allocation,disjoint from session storage. Never pretend it is the frozen keyboard/UART observer record. Semantics:phase/cause/module,gate/native readiness,controller result,poll delivery and whether consumed,logical pointer/suppression/window/pattern/press count,last complete RAM frame,publication stage/completed rows and last complete published frame. Keep finite diagnostics saturating while actual events remain independent. Reset current-turn receipt/progress so stale success is not reported;publish full-frame success only after every row succeeds. Binary offsets/size and native API signatures must be documented/reviewed with implementation before any candidate or external parser;none is installed by this contract. Bypassing UART explicitly means no existing UART telemetry on this path.
