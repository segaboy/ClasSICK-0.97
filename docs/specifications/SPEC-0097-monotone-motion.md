# SPEC-0097 - Optional monotone motion coalescing

2026-11-05; original engineering contract, SRC-0598. This narrowly extends SPEC-0065 with an optional producer operation; the existing cs_inbox_push behavior, capacity16, loss and claimed-record lifetimes remain unchanged. No historical Macintosh behavior is claimed.

New API cs_inbox_push_motion has the same inputs, metadata/argument/refusal precedence and fallback semantics as cs_inbox_push. Before fallback, it may combine incoming displacement with the final unread record only in READY with at least two unread records. It never reads or writes the claimed last record. The final unread record's buttons must equal both its predecessor's buttons and the incoming buttons. Thus neither a button transition nor the baseline is merged. Both final and incoming displacements must be nonzero vectors. Each component's direction must agree (zero may combine with either sign); checked int32 sums must fit. On success write only that tail record's dx/dy, leave count/order/buttons/metadata/claim unchanged, and return new CS_INBOX_MERGED=11. Otherwise use the unchanged push behavior, including overflow loss if full. Never merge a reversal, button edge, PRIMING/baseline, unrepresentable sum or invalid metadata. Original strict push stays strict.

The caller owns the same single non-nesting producer, foreground serialization and short exclusion as SPEC-0065. The tail is unread, distinct from the claimed copy. Coalescing preserves the terminal pointer/window result for this original scene's monotone per-axis motion with unchanged buttons, including clamping; it deliberately omits intermediate paints and reduces delivered-record count. It is not admitted for guest callbacks, raw input clients or chronology-sensitive APIs. Native collector binding is separately tested; only the experimental SHORT profile may opt in. Hard overflow/capture-loss cancellation remains. Tests must include button-press hit testing, reversals, boundary clamping and a claimed-record sentinel, plus strict API preservation. Worker proposals are not passing tests or historical evidence.


Lead review: core/input/pointer.c ptr_axis clamps before addition (including int32 extremes); button suppression changes only with button state. The original window consumes absolute pointer positions and preserves its press-time grab offset. With unchanged buttons and per-axis monotone motion, terminal pointer/window coordinates agree; intermediate event flags, paints, delivery counts and loss counts need not. The latter counters continue to count delivered records and actual hard losses, not raw arrivals. A zero tail or incoming vector uses strict fallback. tests/window-motion-integration.c checks the real graph and complete final frames, including button hit positions, reversal and clamping. This is not admission for arbitrary callback clients.

SHORT alone uses the optional push. Its saturating motion_merges counter counts accepted merges, independent of uncertain-motion drops and hard losses. MCM1 is two uint32 words (tag 0x4D434D31 then copied merge count), explicitly initialized and copied by the existing bounded observation section; read paused. No descriptor capacity increase or additional exclusion region. Normal collector remains strict. The worker's pure clamp-model test is supplementary; the lead's full owner/render test is the integration authority.
