# 286 surface numeric validation experiment

2026-11-01; baseline public `f905096`; SRC-0392 / SPEC-0067 / IMPL-0106 / TEST-0140. This is an original isolated numeric model following the existing [surface width proof](c16-surface-width-proof.md), not a replacement for `core/graphics/surface.c` or a native surface provider. It models a storage-present flag, format, 32-bit signed dimensions and 16-bit stride and storage size; it returns the same surface result codes in the documented order under the pinned 16-bit `SIZE_MAX=65535` and `PTRDIFF_MAX=32767` premise. It never dereferences a storage pointer and cannot establish its validity, extent, segment ownership or alignment.

The model rounds monochrome row width using shifts and a low-bit test; rejects RGBA widths above 16383 before multiplying; checks row representability and stride; then checks height against `32767 / stride` before multiplication. Positive width and the stride check establish a nonzero divisor. On successful preflight the computed span is at most 32767, so the final 16-bit product is representable. The experiment does not change the flat Mac or PC implementation, nor the 286 binding or boot path.

A separately written wide-arithmetic reference in the host test checked 123,200 boundary combinations and 2,000,000 fixed-seed cases, including invalid formats and dimensions, width/stride/storage boundaries, overflow and result precedence. Another 100,000 host cases compare directly against `cs_surface_init` with small dimensions and spans representable under both host and C16 limits. The integrated test passed on Clang x64, GCC x64 and Clang i686 Windows builds, and on a Clang x64 AddressSanitizer/UndefinedBehaviorSanitizer build. The CMake/CTest target `pc286.surface-numeric` also passed. Five separate scratch mutants were each rejected by an actual mismatch: broken mono rounding, a too-small RGBA limit, an excessive span limit, rejection of an equal stride, and rejection of equal storage. The first attempted RGBA mutant was caught by a later redundant check and did not fail; it was replaced with a defect that changes observable behavior. A first sanitizer execution lacked the runtime DLL on PATH; after adding the existing compiler bin for that invocation it passed. GCC initially rejected ambiguous test indentation under `-Werror`; after formatting that test statement it passed. These host checks do not execute 16-bit code.

The independently pinned Open Watcom tool and selected-header identities were verified against `scripts/pc286-toolchain-lock.json`. The final model compiled in small, medium and large data models at `-od` and `-os`: six unlinked objects, each reporting 80286/USE16 and no external imports. This shows that this numeric model needs none of the previously observed `__U8M`, `__U8DQ` or `__U8DR` imports in these configurations; it is not a whole-surface helper-closure proof. `-s` suppresses the compiler stack check for these unexecuted probes and is not a production stack policy.
