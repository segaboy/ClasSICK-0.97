# File Manager read and write through a guest parameter block

SPEC-0136 / IMPL-0166 / TEST-0227, 2026-11-19. The Mac and native 286
opened an existing MFS data fork by name, wrote 96 guest bytes at offset
1,000 and read them again in a fresh guest. That request touches two
nonadjacent physical sectors (LBAs 17 and 22). The original disk kept its
initial hash. Each exported disk matched an independent full-image oracle.
The Mac repeated the operation on tagged Disk Copy 4.2 media.

On the Mac, the probe executes the actual 68000 words A002 and A003 with
the PB address in A0. The native line-A exception handler calls ClasSICK's
file service, updates the saved PC, and returns with RTE and the result
in D0. On the 286, an explicit native instruction step fetches each word at
the 68k frame's PC from executable guest memory, checks the PB and buffer
against the mapped RAM, runs the same file service and advances the guest
PC. Each target uses its own native disk provider.

The binding owns a decoded entry and mark for one named fork. Published
parameter fields and mode values follow 1985 Inside Macintosh II-100 and
II-110. The 286 near-backed instruction step and the Mac test vector are
bounded entry points. A complete banked 286 CPU routing path, historical
error/CCR parity, PBOpen/PBClose file-reference allocation, growth, creation,
patch dispatch and the installed Finder save workflow remain open.

The original fixtures exercised all four positioning modes, a short EOF read
that returned three of ten requested bytes with error −39, a stale reference
that returned −51, and a protected cold-open write that returned −61. Each
case checked the PB's returned count and position plus D0 and ioResult.
In a hosted failure test the second sector committed before the provider
reported failure. The returned count covered 12 definitely completed bytes,
the mark moved to 512, and reading the full disk showed 524 request bytes
had in fact reached media. The test also checked that overlapping guest
spans, a read-only PB, an invalid buffer, unsupported mode and file growth
left disk, mark, frame and PB untouched.

| Qualified file-level workload | Write run cycles | Fresh read run cycles |
| --- | ---: | ---: |
| Mac raw 400 KiB | 97,854,892 | 50,139,686 |
| Mac tagged DC42 | 100,303,970 | 52,588,750 |
| Native 286 transfer image | 6,023,694 | 3,967,860 |

All 22 BootHush runs passed. Six runs exercised the file-level workload
above; the other 16 checked the underlying sector/fork error and mutation
controls. Release and ASan/UBSan each passed 24 file-service assertions
and 60 fork-writer assertions. The first Mac link detected an unintended
`memset` import; the final freestanding payloads linked without runtime
imports. The Mac writer occupies 12,560 bytes before ROM padding. The
286 writer occupies 11,066 bytes with 7,876 bytes of BSS.
