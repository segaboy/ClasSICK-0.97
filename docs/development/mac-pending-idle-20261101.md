# Pending-only idle experiment

2026-11-01; SRC-0592 / SPEC-0093 / IMPL-0108 / TEST-0151. The [loss breakdown](mac-loss-counts-20261101.md#pending-mismatch-breakdown) motivated an opt-in experiment that returns no decision when the producer sees supported pending bits but stable, unchanged A/B/button endpoints in READY state. The experiment does not change the default policy. It can silently miss unobserved even transitions, so it is not a proven safe hardware policy or a release candidate.

Both normal and fast experimental model suites passed alongside the two loss-count suites in four focused Windows GCC CMake tests. The new tests exercise 12 stable pending/phase combinations, retained movement, changed-level/no-pending loss, changed button, unstable samples, quiescence, PRIMING, invalid inbox metadata and unsupported pending bits. The two experimental model suites also passed Windows Clang AddressSanitizer and UndefinedBehaviorSanitizer. A separately compiled mutant missing the A-change guard was rejected. These are synthetic IO checks, not hardware timing results.

The normal fast/invert-3 image rebuilt byte-identical to `920d90bd16b204d4b159356f274273fff02c00f4a960c0cd78880c7ffb7bba1e`, with the experiment disabled. The instrumented experimental image built as matching twins, SHA-256 `508ba4dab1b2e68735eea0f1e44b1c8102e4d3738dfe1666f436d33838cd7f58`, and an independent later twin rebuild from the final recorded inputs produced the same hash. During the first build, a compile-time assertion was briefly added and removed while compilation was running; the first manifest recorded the assertion-bearing header. The later rebuild with that exact header removes any inference about which version a particular first-build compile read. The final input hashes match the recorded files.

One fresh isolated Snow Early128K session booted that original experimental ROM. Its own MLC1 and MLP1 records were read before and after scene positioning, resume, sixteen guarded host upward movements and pause. The helper reported all sixteen Windows events accepted, but capture was not verified. During the full interval the trace gained **549 pending losses and four unstable losses**; the A and B pending-with-unchanged-level counters increased by 248 and 549 respectively. One rejected sample can contribute to both counters. [Raw own-record prefixes](../evidence/traces/2026-11-01/mac-pending-idle-experiment.json). Setup and pause can contribute, the instrumented builds affect timing, and this single run does not establish per-event causation or usable motion. The owned process was externally closed and the ROM was unchanged; no guest shutdown is claimed.

The narrow alternative **did not clear the observed blocker** and is not adopted as a release fix. The counters do not explain which additional predicate prevented its no-decision branch on each later loss. Further work must identify the producer phase, button state and other-channel changes around these mismatches without assuming that unchanged endpoints mean no physical transitions. Human input, physical polarity and the paired release remain unqualified.
