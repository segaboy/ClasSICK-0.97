# Overwriting existing MFS forks on the Macintosh and 286

2026-11-19. SPEC-0128 / IMPL-0158 / TEST-0219. Both native probes
overwrote bytes in existing data and resource forks on disposable,
independently generated volumes. Fresh BootHush guests read back all 2,967
logical fork bytes, and the host independently compared the entire exported
image byte for byte. File creation, growth and File Manager trap dispatch
remain open under the [ROM parity criteria](original-rom-parity-20261119.md).

The shared writer validates the complete allocation chain before I/O, even
for a request that touches only the first byte. A nonempty request checks
both volume lock bits and the entry's file lock. A full-sector overwrite
goes directly to the provider. An unaligned edge requires a read so its other
bytes survive. For a failed write, progress reports the known completed
prefix and flags the failed sector as uncertain. Recovery requires a reread.
Exclusive access, truthful metadata with no other owner of the target
allocation, and a reader and writer addressing the same volume are caller
requirements. The operation does not allocate storage or update timestamps.

| Case | Verified behavior |
| --- | --- |
| Five successive requests | Nine sector writes and six edge reads across both forks, two files, a fragmented chain and a final partial sector. BootHush exported the expected original-format image. |
| Acknowledgement lost after the second sector commit | The guest reported 12 definitely completed bytes and uncertainty at LBA 17. The exported volume included 524 changed request bytes. A cold read established the actual outcome. |
| Partial-sector read failed at LBA 23 | The guest reported 1,036 definitely completed bytes and issued zero writes to the failing sector. The exported volume and fresh read confirmed that prefix. |
| Lock and malformed-chain controls | Host fixtures exercise both volume lock bits separately, the file lock, both forks, and a bad final link outside the requested range. Preflight refusals preserve progress and issue zero callbacks. |
| Four deliberate implementation defects | Skipping chain validation, ignoring volume locks, mapping to the wrong fragment and overcounting the failed-sector prefix each reached its expected failure marker on both processors. |

The 22 native runs comprise seven write/fresh-read pairs and eight mutation
controls. Mac tested all three write outcomes on raw 400 KiB media and also
tested the successful sequence on a tagged Disk Copy 4.2 container. Whole
container comparison checks all original tags, header fields and calculated
checksums. The PC used a 400 KiB logical region within a 1.2 MB transfer
floppy. The reboot used a separate reader payload and the exported region,
copied byte for byte. Fresh reads ran with write protection on both targets.
The 286 inspector compared every loaded payload byte. The Mac inspector
checked the completion word, seven fault words and the full guest report.
Both Release and AddressSanitizer/UndefinedBehaviorSanitizer builds passed
60 hosted assertions, including complete media comparison after a torn write.

Mac BSS ended at 0x2B48. The 286 baseline used 7,484 bytes of BSS. Native
links required no runtime library. These figures describe diagnostic builds.
The first Mac link revealed that whole-structure assignments pulled in
`memcpy`. The probe now retains references to its providers for the
synchronous call. The final run audited the imports of all Mac probe variants.
