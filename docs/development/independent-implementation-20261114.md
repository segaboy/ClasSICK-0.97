# Independent implementation and provenance

Owner direction, 2026-11-14: ClasSICK 0.97 is an independently authored,
Macintosh-compatible system, legally distinct from Apple. This policy replaces
the earlier blanket emulator-implementation exclusion and automatic exposure
stop and separation requirements where they conflict. Historical policies,
decisions, provenance and exposure records remain preserved. This project
policy is not a legal opinion or guarantee.

## Boundaries

- Develop original ClasSICK OS and ROM implementation, artwork and tests.
  Behavior, published interface facts and eligible hardware specifications can
  inform independent designs; do not copy protected expression.
- Do not fetch, inspect, copy, translate, disassemble, decompile or use Apple
  or Microsoft implementation or ROM/System code, leaked material, prohibited
  derivatives, or copied protected assets as implementation inputs. Reference
  system use, when separately authorized, is black-box only and does not permit
  redistribution of protected code, media, screenshots or assets.
- Developers may develop and consult their own original BootHush implementation
  while working on ClasSICK. Such exposure alone does not stop work or require
  another implementer. The prior recorded BootHush exposure is not an obstacle
  under this owner decision. A tool/model observation is not hardware proof.
- BootHush contains third-party components. Review the particular material's
  source, rights, license, provenance and compatibility with the independent-code
  goal before using it as an input or importing it. Project ownership of some
  files does not automatically admit every dependency. No third-party code or
  game-derived code is automatically admitted by this amendment.
- If a source or contribution has uncertain rights, quarantine it and resolve
  that specific issue before incorporating or publishing it. Keep a factual
  record and continue independent work. Prohibited material stays excluded.

## Evidence and release

Record relevant sources and revisions, distinctions between documented facts,
emulator observations, hypotheses and physical measurements, implementation
choices, tests, limitations and third-party licensing. Approved historical
contracts remain useful; an independently written specification or separate
worker is a tool when useful, not an automatic prerequisite solely because the
developer also works on BootHush. Preserve specific held UART work and other
unrelated scoped controls until reviewed for an authorized change.

This amendment changes process, not the Mac/286 release acceptance criteria,
GPL-3.0-or-later license, paused x64 direction, physical and human qualification,
reference-trial permissions, provenance review, or separate publication gate.
It does not establish compatibility, approve reference trials or authorize a
release. See [Mac/286 direction](mac-286-paired-direction-20261114.md).
