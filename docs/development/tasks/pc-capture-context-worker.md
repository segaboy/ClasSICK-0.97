# PC capture-context read-only diagnostic proposal

No prior Windows sample, Microsoft or Apple implementation, manuals, emulator source, ROM, private material, web, shell, editing, delegation or execution. Return proposed artifacts only; the lead will review and integrate. Project code is GPL-3.0-or-later, inbound equals outbound. Do not claim source or target tests ran.

Goal: a bounded read-only Windows C99 context snapshot function for an already selected owned emulator window, to distinguish host cursor/capture observations from guest delivery. Caller separately verifies its owned process, image, window and input desktop. Function takes HWND and expected DWORD PID from that caller; confirm the window belongs to that PID and refuse on invalid inputs or mismatch. It must not choose a window or process, activate or move windows, modify settings, clip/move cursor, inject input, capture screenshots, enumerate windows, read process memory or use network. Getters are observations only; never declare capture, GUI delivery or guest movement a pass from these. No other desktop/client interaction.

Return one complete self-contained C source file with a narrow function `int wih_context_snapshot(HWND window, DWORD expected_pid, FILE *out)` and necessary headers, no main. Emit one JSON line using numeric/boolean/null values only. Every failed getter must yield null for its fields, never uninitialized values or a false success. Include: target PID check; cursor screen and physical screen positions separately; clipping rectangle; global cursor information flags; target window DPI-awareness context as an opaque context value (do not infer a DPI or dereference it); the target thread GUI capture window PID, and whether capture belongs to the expected PID. Verify structure sizes before applicable calls; do not output unrelated window titles, other process names or screen content. Per-result failures should be visible in JSON. If DPI context cannot be represented portably, return a clearly named present/absent field instead. Ensure valid output on failure, check stream errors, and avoid undefined behavior on Windows x86 and x64. State prerequisites and any necessary `_WIN32_WINNT` setting. Prefer getter APIs listed below and standard declarations from Windows headers. Return concise negative/edge cases as a test proposal, with no claims of execution.

Reviewed interface facts, not implementation samples:
- GetWindowThreadProcessId reports a window's owning thread and optionally process ID; zero indicates failure.
- GetCursorPos returns cursor screen coordinates; GetPhysicalCursorPos returns physical screen coordinates.
- GetClipCursor returns the current confinement rectangle, or screen dimensions when not confined.
- GetCursorInfo reports global cursor information; caller initializes its size member.
- GetWindowDpiAwarenessContext returns the specified window's awareness context, independently of the querying thread.
- GetGUIThreadInfo queries GUI state of a selected thread; caller initializes its size member. Its capture-window handle can be checked with GetWindowThreadProcessId. Treat absence of a capture window separately from a failed query.
- These facts derive from documented public API interfaces; they do not establish how any emulator or operating system implements capture.

Output JSON object with exactly `source` (complete source as a single string), `tests_proposed` (array), and `handoff` (result, actionable_findings, tests_executed=[], blockers, decisions_needed; <=180 words). Max 220 source lines. You must not use shell, edit, internet or other files. Do not expose credentials or infer physical or release qualification.
