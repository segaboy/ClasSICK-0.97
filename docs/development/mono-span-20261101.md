# Monochrome fill spans

2026-11-01; SRC-0592 / SPEC-0001 / IMPL-0105 / TEST-0139. Mac drag trials showed visible redraw taking several seconds in some observations. The original monochrome fill wrote every pixel individually; that is a plausible contributor, not a measured target-side cause. The shared fill now updates complete interior bytes and masks its first and last byte, including a one-byte intersection. Validation, error precedence, clipping, untouched pixels and padding, and the RGBA behavior retain SPEC-0001. The implementation uses byte accesses only and adds no allocation or library dependency.

An independent per-bit oracle checked 2,707,200 small whole-buffer cases over widths 1 through 25, all endpoint alignments in the tested range, clipping, reversed/empty rectangles, two colors, three backgrounds, minimal and padded strides, and guard bytes. Additional selected wider cases cover widths 255, 256, 511, 512 and 513. Four separately compiled faulty variants with broken leading mask, trailing mask, one-byte mask and padding preservation were rejected; an unmodified control passed. The surface suites and affected product, cursor, window-scene, window-input, PC and Mac hosted checks passed with GCC and Clang sanitizers. Two freestanding checks initially failed because their object targets had not been built in the focused run; after building those targets, both checks passed. Independent intentional AddressSanitizer and UndefinedBehaviorSanitizer defects were detected before counting sanitizer results.

The six surface checks also passed in a 32-bit Windows Clang build. Its first configuration failed because Python was not found; setting the existing pinned Python path allowed configuration, compilation and the checks to pass. This is a hosted 32-bit result, not a 286 execution result.

On this Windows host, a narrow benchmark of 500 repeated 144-row, roughly 500-pixel-wide fills per sample, compiled with GCC `-O2 -ffreestanding -fno-builtin`, had a median of 0.035361 seconds before and 0.000250 seconds after across five samples each. Both ended with checksum `5a77fa10`. This short hosted benchmark is not a measurement of redraw latency, a Macintosh or 286, or a guarantee of speedup for other workloads.
