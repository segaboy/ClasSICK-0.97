# Native MFS media integration - 2026-11-18

SRC-0612/0613/0614/0615; SPEC-0111..0115; IMPL-0144/0145; TEST-0209.
The original MFS workload now mounts, enumerates, validates and reads complete

This is read-only filesystem/device integration. It does not boot System/Finder,

and [RAM-provider MFS tests](mfs-volume-20261118.md) retain their separate scopes.

## Workload and native transports

The original `probes/storage/mfs-media.[ch]` workload calls
`cs_mfsv_mount`, `cs_mfsv_directory_next`, `cs_mfsv_fork_validate` and
`cs_mfsv_fork_read` in sequence. It counts both forks of every directory entry,
including an absent fork, and reads nonempty logical data in chunks of at most
256 bytes. A rolling rotate-left-five/XOR digest covers logical bytes in
directory order, data fork before resource fork. The diagnostic reports twelve
32-bit words; it never prints the bytes it reads.

Every read pre-fills output with `a5`. Failed requests must preserve the entire
output, and successful requests must preserve its unused tail. Success returns
`B7`; a normal read failure returns `D4`, while a failure that modified output
would return `DF`. Metadata/chain failures have separate markers. These markers
are diagnostics authored for this workload, not historical OS error codes.

`probes/pc286/boot-mfs-media.c` binds the native SPEC-0113 block provider to
800 logical sectors beginning at PC floppy sector 60. The original diagnostic
loader and linked 286 program occupy earlier sectors. The private logical-sector
copy is an explicit transfer arrangement, carries no Mac tags, and is **not the
final native 286 product bridge** or a claimed bootable original Mac disk.

`probes/mac128k/mfs-media.c` binds the native SPEC-0114 IWM provider and runs
the same workload through actual modeled drive reads. Both lanes use the validated
logical bytes copied from the selected DC42 container into an external transfer
image. The Mac provider therefore receives the logical raw representation in
this workload; tagged DC42 transport qualification remains in the separate
[provider receipt](mac-floppy-provider-20261118.md).

The native links use no default/runtime library. The 286 run inspects every
loaded byte of its original 4,790-byte program in two ranges of at most 4,096
bytes, plus the numeric report. It does not inspect disk buffers. Linked BSS is
4,478 bytes, beginning at offset 4,790. The Mac run inspects only its seven-word
diagnostic and twelve-word report; its raw ROM payload is 5,752 bytes and fits
the existing 64 KiB ROM and reserved data/BSS constraints. These are diagnostic
measurements, not whole-system stack/RAM budgets.

## Original fixture and failure controls

The independent generator in `scripts/Test-MfsVolumeMedia.py` constructs an
800-sector disk from the reviewed contracts. It contains two directory entries
in separate blocks with zero tails, sixteen 1,024-byte allocation units and
eleven free units. Its high-first map links file data through allocations
`2 -> 5 -> 3`; allocations 4 and 6 hold separate resource forks.
The first file has 2,437 logical data bytes and 17 resource bytes. The second
has an absent data fork and 513 resource bytes. Independent arithmetic generates
the physical payloads and calculates the expected concatenated logical digest.
No protected disk bytes informed these fixtures.

result. Every input medium remains unchanged.

The failure is late in the overall file scan. Because these particular requests
are aligned chunks of at most 256 bytes, it does **not** independently test a
failure on a later sector within a single multi-sector fork request. The separate
TEST-0204 suite owns that staging/publication claim and its mutation controls.
No production source mutation or bug fix was needed for this integration.
