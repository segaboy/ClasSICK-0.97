# 286 checked-access qualification

2026-10-30; baseline b50d50452cb6d1c6b97edfb3de56b9f54f9c6291; SRC-0566, SPEC-0086, IMPL-0096, TEST-0115. The owner previously approved bounded review, test and conditional integration of the separate original 286 contribution. This adopts only r4 slice A as an isolated model, with the correction below. It does not adopt CLEANROM, the Mac lane, or the proposed capability/store slices.

The model implements checked big-endian byte/word/long reads and writes over existing segmented spans. Refusal leaves output/backing unchanged under the stated caller obligations; bytes are resolved before a store. It is not wired to the 286 boot path or production guest memory. The contract states the additional BACKING, STALE and BINDING outcomes and the limits of guest.c parity.

The submitted closure compiled under near-data Open Watcom `ms` and `mm` models despite requiring far data pointers. The lead added an original target-specific pointer-size assertion to span-bind.c. Both near models now fail at that precise assertion. Pinned Open Watcom 2026-10-01 then compiled four mc/ml, od/os closure objects; each reports 80286/USE16, the expected public symbols and no unresolved imports. Two expected guard refusals were also checked. Objects were not linked or executed; no whole-ISA, ABI or stack proof is asserted. Original author files remain byte-identical outside Git; the integrated bind source differs by the explicit guard.

Each of four Windows host profiles (GCC x64, Clang x64, GCC i686, and Clang ASan/UBSan x64) passed the three actual tests: 200,000 author differential operations against a flat model, 46 author literal cases, and 300,000 author-generated parity operations against existing guest.c. The source of the literal oracle and generator is the contributor, not an independent author. Three independently introduced defects in separate scratch copies (ignore stale epoch, ignore late null binding, omit final write byte) were each detected by an actual failed assertion. Seven incompatible compiler-profile combinations refused before creating output.

The prior default, catalog, store4 and span-build profiles also compiled: their 22 disassembly listings match the previously recorded listings after excluding the generated module path. Raw closure object hashes differ when generated in a different directory, so byte identity is not claimed for those objects. The default objects are byte-identical. No new target, emulator, hardware or reference run was performed. No other AI tool was used.

Remaining: independent review of source provenance, actual segmented backing provider, stable ownership/nonaliasing and lifetime, target link/ABI/stack and execution, performance and boot qualification. The Mac motion/drag and PC GUI drag blockers remain open; this does not make the paired release ready. The separate capability and placement proposals are not adopted here.
