# Mac baseline latch experiment, 2026-11-03

SPEC-0095 / IMPL-0110 / TEST-0153. An independent review of project-owned code identified a race: a signal may become pending after the entry RR3 read but before the first baseline snapshot. The current model then accepts the changed endpoint as its baseline and reports the still-pending signal as a loss in PRIMING. The original driver reproduced this with an injected edge in the existing source-informed model. The opt-in experiment checks pending signals again before publishing a stable WAIT baseline, retaining pending input for the next service rather than acknowledging it or inventing movement. This model result does not establish the cause of observed Snow losses; the extra read also takes time and may delay a baseline during continuous motion. Normal builds remain unchanged.

The focused normal and fast collection tests passed, along with the existing register-model, fast-core and conditional-latch tests. The new cases cover the original race on both channels, a pre-existing pending bit, unsupported bits, unstable sampling, a subsequent coherent edge, and edges immediately before and after the new check. Both variants passed Clang address and undefined-behavior sanitizers, with 51 checks each. A deliberately disabled late-pending guard was rejected by the fixture. The fast/invert-3 build with the experiment disabled reproduced the prior ROM SHA-256 `920d90bd16b204d4b159356f274273fff02c00f4a960c0cd78880c7ffb7bba1e`.

Three isolated Snow Early128K sessions used original ROMs, no disks or shared folders and guarded host input. Windows accepted the requested events; the helper did not independently verify capture. The following are observations of these particular sessions, not physical-hardware or human qualification:

* Instrumented fast/invert-3 candidate `ce2f61c9d6fb1d884972d52c16e826a9f14598ba090e518dc4791b63beecd8e7`: during setup, sixteen upward movements and pause, its own trace showed six additional unstable losses and no additional pending losses. One pending loss already existed. The final record showed 22 cumulative deliveries. Timing and diagnostic instrumentation preclude attributing this result to the new check.
* Uninstrumented fast/invert-3 candidate `769a0dd52beee3d62b09aa14b9824aa09fb071ab5afe4bda7230ab9047cf4573`: a guarded click changed the checkerboard and counter; movement reached the title bar; held movements dragged the window approximately 16 pixels right and back; later unpressed movement left the window in place. Its final record contained 138 cumulative deliveries and 20 cumulative losses. There was no pre-test trace, so losses cannot be assigned to a particular gesture. This is a bounded host-only observation, not a loss-free or human-input pass.
* Instrumented normal-collector candidate `1c64c23911cbbd2e9d69678d749c29107b1bbff4e1db41ef3dc4de630c6f6e39`: the comparable setup and sixteen movements produced 16 additional unstable and one additional pending loss. The final record showed zero cumulative deliveries; no drag was attempted.
