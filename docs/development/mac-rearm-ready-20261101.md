# Baseline-consumption rearm experiment

2026-11-01; SRC-0592 / SPEC-0094 / IMPL-0109 / TEST-0152. A [previous instrumented Snow run](mac-loss-counts-20261101.md#pending-loss-context) found all five observed pending losses in PRIMING. The driver had re-enabled the SCC master when it queued a baseline, before foreground consumption. This opt-in experiment keeps SCC master masked through a valid PRIMING interval, preserves pending input without reading or acknowledging it, and performs the normal strict check once READY before rearming. It changes interrupt timing and may coalesce unseen edges; the default policy remains unchanged. It is not an established physical-hardware behavior.

Four focused Windows GCC CMake tests passed: the normal and fast baseline controller suites and both experimental rearm suites. The new tests cover pending retention both before and while a baseline is claimed, successful rearm only after completion, strict mismatch loss, coherent edge delivery, recovery, invalid in-flight metadata and stop. Both experimental suites passed Windows Clang AddressSanitizer and UndefinedBehaviorSanitizer; an early-rearm mutant was rejected. Three unsupported builder combinations refused before creating output. Rebuilding the fast/invert-3 profile with the experiment disabled produced the previous exact hash `920d90bd16b204d4b159356f274273fff02c00f4a960c0cd78880c7ffb7bba1e`.

An original instrumented experimental fast/invert-3 ROM built as matching twins, SHA-256 `a1008c22c574e94779d01dfa0120aa2a9f71bbb903116ae08e7fbbbd4a30afa9`, and its 47 recorded inputs match the trial source files. An uninstrumented experimental twin build also passed, SHA-256 `de97a70a6cd768316900791259a9eefcb41188213cdbf5f659b74deecefb5a8c`; it was not booted. One isolated Snow Early128K session booted the instrumented image. Before and after a sequence including scene positioning, sixteen guarded host upward movements and pause, its own [MLX1, MLP1 and MLC1 records](../evidence/traces/2026-11-01/mac-rearm-ready-experiment.json) showed 53 additional pending losses, all classified as READY with no sampled endpoint or button change, and 32 additional unstable losses. No pending losses were classified as PRIMING during that interval. Windows accepted all sixteen guarded events; capture was not established. The owned process was externally closed, its ROM was unchanged, and no guest shutdown is claimed.

This run demonstrates that the candidate did not eliminate the observed input losses. It does not quantify a speedup or prove why the signal was pending: session timing, UI actions and added diagnostic work differ from the earlier run. The candidate does not establish working dragging, human input or physical polarity and is not release-qualified. The PC and human-input gates remain open; the paired release has not been published.
