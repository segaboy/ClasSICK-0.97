# ClasSICK 0.97 paired experimental preview

ClasSICK ROM **0.4.0-alpha.1** and ClasSICK PC Preview **0.2.0-alpha.1**
show the same original movable window, cursor, click counter and pattern on
native 68000 and native 286. This is an experimental preview. System software
and the separate game port remain incomplete. No Apple ROM, Apple System or
Microsoft executable is required.

The package includes both targets, corresponding source, GPL-3.0-or-later
license, exact checksums, test reports, screenshots, a checkpoint GIF and a
continuous sampled Mac video. `RELEASE.json` states the qualification scope.
The older review documents under `evidence/history` preserve their original
pending status; they are not the current release decision.

## Verify and boot

Run `python -B verify-package.py --package PATH_TO_UNPACKED_PACKAGE` before
creating additional files inside the package. The verifier checks exact file
membership, hashes, source correspondence and license identity. It is not a
publisher signature or an independent provenance review.

Use BootHush SHA-256
`9dc2f28425bafd10114cfde9ab5c439d61234873854cfa1c211cdcfb26bda82d`,
the tested active Mac/286/NES build. Emulator and compiler binaries are not
bundled. In PowerShell, set `$preview`, `$bh` and an existing `$captures`
directory outside the package. These bounded commands run headlessly:

```powershell
& $bh --machine mac128k --rom "$preview/mac/classick.rom" --cycles 100000000 --timeout-ms 20000 --until 0xcac:4:16 --mouse-edge-cycles 4096 --mouse-dcd-invert 3 --mouse-vbl-guard 4096 --frame "$captures/mac-ready.pbm"
& $bh --machine pc286 --hard-disk "$preview/pc286/hard-disk.img" --cycles 10000000 --timeout-ms 20000 --until-post 0xb0 --ega-font "$preview/font/diagnostic-8x14.bin" --frame "$captures/pc-ready.ppm"
```

The Mac ROM is 64 KiB for BootHush's Macintosh 128K/68000 profile. Press its
title bar and move while holding the button to drag; release to stop. A fresh
content press changes the pattern. Use **edge spacing 4096, DCD inversion 3,
VBL guard 4096**. Spacing 2048 reproduced 27 guest motion omissions in the
retained owner trace and is not a supported release profile. No physical
polarity/timing or human relative-speed qualification is implied.

The PC disk is 21,411,840 bytes for the modeled PC/AT 5170, 6 MHz, 640 KiB,
EGA and 615/4/17 disk geometry. Arrows move 16 pixels per make. **Hold Space**
for button-down and release Space for button-up; repeated makes do not add
clicks. This is a keyboard pointer adapter, not a PC mouse driver.

For optional local human use, BootHush provides a bounded native testing
window and logging through `scripts/run_human_session.py`; its own guide
documents capture and release. Human testing is not required to reproduce
this release's automated evidence. The last active owner Mac test failed
relative-speed expectations; those limitations remain open.

## Installer

The 1.2 MB floppy installs onto a newly generated, all-zero disk of the exact
geometry above. Type `INSTALL` then Enter. Any other input cancels without
writes. The installer rejects any occupied target byte, validates the staged
CRC, writes and verifies its payload, then commits the boot sector last.
The supplied hard disk is the exact successful installation result.

This fixed-profile whole-disk installer is not partition-aware and is not
qualified for a physical machine or a disk containing another operating
system. Reproduction scripts only open disposable image files.

| Path | Code | Meaning |
| --- | --- | --- |
| Boot | B0 | Initial scene ready |
| Boot | E1 / E2 / E3 | Profile / exhausted read / payload CRC failure |
| Install | A0 / AC / AD | Prompt / verified success / cancellation |
| Install | E1 / E2 / E3 | Profile / staged CRC / preflight read failure |
| Install | E4 / E5 / E6 | Occupied target / exhausted write / verification failure |

## Rebuild and evidence

Unpack `source.zip`; `RELEASE.json` identifies its committed revision and
the image-producing inputs checked against the frozen review. `build-source.zip`
retains the exact earlier source and all 80 frozen input identities, including
review documents subsequently updated after human feedback. Unrelated local
work is excluded. Tool versions, exact build commands and hashes are in the
retained build reports. The tested Mac and PC image bytes match that review.
No WSL is needed. With the pinned Windows-native tools from those reports:

```text
python -B scripts/Build-LoadedAppROM.py --windows-native --tool-root M68K_BIN --window-drawing --window-fast-collect --window-short-collect --window-buffered-collect --window-burst-capture --window-capture-capacity 2048 --window-loss-counts --dcd-invert 3 --output NEW_MAC_BUILD
python -B scripts/Test-BootHushPC286SharedSession.py --tool-root WATCOM_ROOT --assembler WASM --host-cc CLANG --emulator BOOTHUSH --output NEW_PC_PAYLOAD --natural-start --raw-keyboard --verify-crc16 --verify-geometry --retry-reads --hard-disk
python -B scripts/Build-PC286PreviewMedia.py --session NEW_PC_PAYLOAD --assembler WASM --linker WLINK --output NEW_PC_MEDIA
python -B scripts/Test-MacReleaseInputProfile.py --emulator BOOTHUSH --rom NEW_MAC_BUILD/Os-a/classick-loaded-app.rom --manifest NEW_MAC_BUILD/manifest.json --owner-trace PACKAGE/evidence/final/M1R5.bhmouse --output NEW_INPUT_TEST
```

The font generator and original font are in `font/`. Continue with the media,
paired-parity and capture commands in `evidence/final/`. Use new output
directories; tests deliberately refuse stale identities. The GIF presents
eight completed states at one second each, not simultaneous timing. The MP4
samples guest time at 10 fps. All captures contain original project imagery.
Optional `port-media` demonstrates a separate incomplete prototype; no game
ROM is included. COPYING and COPYRIGHT.md state the project license.
