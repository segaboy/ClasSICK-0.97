# ClasSICK PC Preview 0.1.0-alpha.1

Experimental native PC preview. The surrounding approval record determines publication status; these download notes do not authorize publication.

- Component tag: `pc-v0.1.0-alpha.1`
- Component version: 0.1.0-alpha.1
- Type: an experimental, original native drawing preview for x86-64 UEFI. It is not System 1, not a desktop and not a hardware release.

## What it is

A small original UEFI program (159,232 bytes). It draws the same black-and-white 512x342 scene as ClasSICK ROM 0.3.0-alpha.1, centred on a 1024x768 screen: a ring with rails, six phases, the result 0097 and an input counter. It contains no Microsoft or Apple code or assets. This preview runs continuously. It ignores the usual 60-second deadline and does not quit on Escape; to stop it, close the VM. Older diagnostic modes are unchanged.

## Assets

- `classick-pc-0.1.0-alpha.1-x86_64.efi`: the UEFI program.
- `classick-pc-0.1.0-alpha.1-x86_64.zip`: `EFI/BOOT/BOOTX64.EFI`, the raw boot disk `classick-pc-0.1.0-alpha.1-x86_64.img`, README.txt (how to try it), RELEASE.txt (these notes), COPYING, SOURCE.txt and SHA256SUMS.txt. The 64 MiB raw disk is a mostly empty boot container. It compresses well and is not the size of an operating system.
- `classick-pc-0.1.0-alpha.1-source.zip`: the complete source at the compiled revision.
- `SHA256SUMS.txt`: checksums for the three files above.

No emulator or compiler is included.

## What was checked

- In a headless VirtualBox VM (EFI64, 1 CPU, 512 MiB), 38 mouse events and 5 Space presses were injected over 185 guest seconds. The static scene stayed unchanged.
- CI covered 3150 tests across 11 profiles.

## Known limitations

These have not passed. Each one needs the owner's explicit acceptance:

- After a report of intermittent clicks, pointer capture and focus for a person using the VirtualBox GUI are still unresolved.
- One GUI launch failed before boot with VERR_CPUM_TOO_MANY_CPUID_SUBLEAVES. The unchanged headless fallback passed.
- Physical PCs, booting Apple System 1, native external apps and a complete Linux edition are not qualified.

## Rebuilding from source

On Windows 11 x64, from the unpacked source archive, install the hash-pinned tools and use fresh output directories. Python 3 must be available as `python`:

    ./scripts/Setup-Windows.ps1
    . ./scripts/Enter-DevEnvironment.ps1
    ./scripts/Verify-LoadedApp.ps1 -BuildRoot NEW_VERIFICATION
    ./scripts/Verify-UEFIImage.ps1 -OutlineDrawing -BuildRoot NEW_EFI
    ./scripts/Package-OutlineDrawingPC.ps1 -BuildRoot NEW_EFI -MediaWriter NEW_VERIFICATION/clang-hosted/debug-a/classick_boot_media.exe -TwinWriter NEW_VERIFICATION/gcc-i686/classick_boot_media.exe

The EFI payload is `NEW_EFI/payload/EFI/BOOT/BOOTX64.EFI`; the raw disk is `NEW_EFI/outline-drawing.img`. Compare the payload with the standalone EFI checksum. The raw disk SHA-256 is `fcfc90027a6910fd6f7362a21037ba277286b7dae80667303afd46456086eb2a`; its copy in the demo ZIP has the same bytes. These scripts build and check original code; they do not start a VM.
