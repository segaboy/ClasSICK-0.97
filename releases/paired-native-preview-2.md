## 3. Recommended release goal

2026-10-21 roadmap alignment:the owner's [unified x86-64 PC goal](../docs/development/unified-x64-pc-plan.md),ADR-0067,targets one payload with BIOS/UEFI entries and broader tested hardware. This paired window milestone remains the immediate checkpoint;BIOS support is not a new acceptance condition for this provisional pair. No existing runtime/trial/publication gate changes.

On both native targets the user moves an original cursor and presses on the title strip
of ONE original fixed-size frame. They then drag the frame within the 512x342 logical
canvas. Clicking its content toggles an original monochrome pattern exactly once per press. The window redraws without trails;the original branding and diagnostic counter remain available.
Why release-worthy: this is the first direct manipulation and the first motion input.
It generalizes the existing counter-only redraw to a moving cursor/window. It runs the same shared C on both CPUs, and it
is observable by a human on real input paths.

Proposed versions (engineering choice, provisional): ROM 0.4.0-alpha.1,
PC 0.2.0-alpha.1. A minor bump is justified by the new input capability. Each target
keeps its own identity. A target that does not change gets no new build.

## 4. Scope
In:
- Shared C pointer state: a declared initial position and hotspot,checked accumulation,one logical origin/axis convention and clamping to0..511 x0..341. Final coordinate/overflow rules need the first contract;adapters normalize platform input without importing undocumented acceleration. - Cursor saved-background/restore, with clipping at all 4 edges.
- One original frame object, built by our own design and with original title-strip art.
  It handles hit-test, drag start/track/end, drag outside the frame and outside the canvas
  (clamped), and release, cancel, button held at start, and re-entry after release.
- Dirty-rect redraw of the union of old and new frame bounds. The PC margin stays white.
- Explicit pre-effect refusal versus post-effect fault/cancellation handling. No blanket rollback or return-to-idle promise;define retained effects and safe recovery before implementation.
- Native drawing views provide local coordinates and rectangular clipping;the new window is a reusable bounded native object,not a one-off assembly illustration.
- Keep the64KiB ROM target and current Early128K memory profile. Record actual linked code/static data/stack/workspace costs;refuse overflow or unmeasured extra full-screen buffers. This is not a full128K System feasibility claim.
