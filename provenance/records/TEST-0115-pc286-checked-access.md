# TEST-0115 - 286 checked-access qualification

2026-10-30; SRC-0566 / SPEC-0086 / IMPL-0096. Four host profiles pass the three author suites; three introduced defects are detected. The pinned 16-bit compiler generates four unlinked 80286/USE16 objects, refuses two near-data models at the guard, and rejects seven conflicting options before output. Previous compiler profiles pass with matching listings apart from generated module paths. [Evidence and limits](../../docs/development/pc286-span-access-evidence.md). No target execution, hardware or release qualification.

2026-11-11: the existing hosted parity suite additionally forces four-byte accesses at `0x7ffe`, `0xfffe` and `0x17ffe`, checks each expected big-endian byte across span/bank boundaries, and checks a region-end refusal leaves the read output and last two bytes unchanged. An odd-address write is also refused. The amended suite and four existing viewer/input tests each passed under both Windows Clang and GCC CTest configurations. These tests execute hosted code, not a 16-bit 286 image.

2026-11-11, follow-up: the hosted checked-access suite now independently corrupts each of the 11 span descriptors in four ways (bank ID, offset, zero length and null backing). Each of the 44 cases requires a cross-bank read and write to refuse, leaves the read sentinel unchanged, and compares the entire simulated 1 MiB backing against its pre-call snapshot. The amended `pc286.span-access` test passed under both Windows Clang and GCC. This is a hosted fault-injection result; it does not establish native 286 execution, pointer lifetime or physical-memory ownership.
